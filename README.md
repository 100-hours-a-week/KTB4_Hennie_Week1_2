# 1주차 회고록
## 1. 이번 주에 한 일
이번 주에는 Java의 기본 개념을 학습하고, 이를 바탕으로 간단한 객체지향 프로그램을 설계하고 구현했다. 
처음에는 Java 문법 자체도 익숙하지 않았고, 클래스와 객체, 상속, 메서드, 패키지 구조를 어떻게 나누어야 하는지 헷갈리는 부분이 많았다.

옷장 코디 추천 프로그램을 주제로 정하고, Top, Bottom, Outer, Shoes처럼 옷의 종류를 클래스로 구분해보았다. 
각각의 옷들의 공통 속성과 기능을 가진 클래스로 만들고 상속 구조로 나누면서, 수업 시간 때 배운 기본 개념을 직접 적용해보았다.

이번 주에 다시 깨닫게 된 점은 객체지향은 클래스를 많이 만드는 것에 목적을 두기보다 역할과 책임을 나누는 방식이 꽤 중요하다는 점을 느꼈다.
학습을 병행하면서, 공통적인 속성은 부모 클래스(`ClothingItem`)에 두고, 세부적인 차이는 자식 클래스에서 표현하는 방식을 익혔다.

그리고, 입출력 받는 클래스, 추천 기능 클래스, 옷 클래스로 기능을 분리해 한 클래스에 메서드를 몰아 넣기보다 역할별로 클래스를 나누는 것이 처음 보는 사람에게 코드 파악을 쉽게 할 수 있는 방식이라는 점과 관리 차원에서도 좋다는 것을 다시 한 번 깨닫게 되었다.

## 2. 어려웠던 점
- IntelliJ 툴을 오랜만에 써봐 VSCode와 다르게 Git을 연동하는 법을 다시 익혔다. 
- 어디까지 클래스로 나누고, 어디까지 속성으로 표현해야 하는지 판단하는 게 어려웠다. 예를 들어, TShirt를 클래스로 만들었을 때, sleeveType을 속성으로 둘지 아니면 새로운 클래스로 또 나눠야 할지 고민이 되었다. 하지만, 클래스로 나누면 클래스의 깊이가 깊어져 수업 시간 때 배웠던 의존성이 높아진다는 개념을 떠올려 속성으로 나눴다.

## 3. 잘한 점
모르는 개념이 나왔을 때 그냥 넘어가지 않고, 학습했던 내용을 기반으로 내 방식대로 이해하려고 했다. 
처음에 클래스, 객체, 상속, 참조 타입같은 개념들을 따로 떨어져 학습을 했지만, 직접 구현하다보니 이 개념들을 연결할 수 있던 점을 보아 조금 성장한 것 같다.

## 4. 아쉬웠던 점
- 처음 설계 단계에서 너무 복잡하게 생각하다 보니 구현까지 꽤 오랜 시간이 걸렸다.
처음부터 완벽한 구조로 만들려고 하다 보니 어떤 클래스를 만들지, 어떤 속성을 넣을지 계속 고민을 했다.
실제로 구현을 하나보니, 먼저 단순한 구조로 만들고 이후에 필요할 때 리팩토링하는 방식을 차선책으로 두어도 괜찮을 것 같다는 생각이 들었다.
- 추천 알고리즘도 아직은 아쉬운 부분이 있다. 
<br/>현재는 날씨와 스타일이 모두 맞는 옷을 먼저 찾고, 그 다음 날씨만 맞는 옷, 스타일만 맞는 옷 순서로 추천하도록 만들었다. 이 방식은 구현하기 쉽고 흐름을 이해하기 좋지만, 실제 코디 추천이라고 보기에는 단순한 편이다.
<br/>예를 들어 더운 날씨라도 사용자가 formal 스타일을 원한다면, 날씨와 스타일 중 어떤 기준을 더 중요하게 볼지 세밀하게 판단해야 하는데 현재 구조에서는 이런 우선순위를 유연하게 조정하기 어렵다.
- 모듈화 관점에서도 아직 역할이 완전히 깔끔하게 나뉘었다고 보기는 어렵다.
<br/>`ClosetApp` 사용자 입력과 출력 흐름을 담당하고, `Recommender`는 추천 로직을 담당하도록 나누었지만, 선택 가능한 날씨와 스타일 목록은 입력 클래스 쪽에 있고 실제 추천 기준은 추천 클래스 쪽에 있어 두 부분이 문자열로 느슨하게 연결되어 있다. 프로젝트 규모가 커진다면 입력값 관리, 추천 기준, 의류 후보 데이터가 각각 더 명확한 책임을 가진 클래스로 분리될 필요가 있을 것 같다.

## 5. 개선할 점
다음주부터는 학습한 개념을 정리할 때 정의만 적는게 아니라, 실무에서 왜 필요한지/언제 쓰이는지/다른 개념과 어떻게 연결되는지까지 함께 정리해야겠다.
